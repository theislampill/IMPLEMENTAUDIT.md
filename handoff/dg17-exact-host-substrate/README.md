## Actual host gates required at execution

The job requires the standard `ubuntu-24.04` GitHub-hosted Linux x64 VM and an
unprivileged consuming UID. It checks the real provider environment and a public
repository push event, verifies candidate HEAD/sole parent/tree/delta, requires a
clean checkout, and records the exact image/interpreter observations available
on that run. Image labels are not immutable image identities; the observed
`ImageOS` and `ImageVersion` are retained separately.

`/usr/bin/python3` must resolve to an existing installed Python ELF executable.
Its resolved file and **every resolved ancestor through `/`** must be owned by
UID 0 without group/world write bits. This is the exact helper's ordinary POSIX
route. The separately supported `/implementaudit-python` read-only bridge is not
universally required and is not created or impersonated here. Missing gates
stop the run; no chmod/chown of system Python, its ancestry, or any existing
installation is attempted.

Only after the source and host gates, `sudo install` copies the selected original
files into the new `/opt/dg17-exact-a297-<run_id>-1/source` tree. Its ancestry and
files are UID0-owned and not writable by the consuming UID. The installed driver
and manifest are read-only at the sibling `driver/` path. The new sibling
`fixture/` is explicitly writable by the unprivileged consumer. Root custody of
the source is separate from the fixture's necessary write authority.

The helper receives a small explicit environment with a system-only PATH and
no caller Git configuration, credential values, Python import paths or original
controller state. All calls use the exact installed original bytes. Hashes and
physical identities are checked again at the end. The helper's own source and
custody checks remain intact. There is no library monkeypatch, copied interpreter
identity, fabricated native callback or changed acceptance predicate.

## Prospective episode and expected results

The only Git commit created by the driver is the explicitly disposable fixture
baseline. It contains two harmless task files, has no remote, and does not create
a product/source commit. All new fixture controller refs stay in that fresh
repository. No existing/private/protected controller or remote ref is accessed.

The planned **16 top-level public helper calls** are below. The helper may make
its existing internal read calls; the count is not a process census.

| Calls | Operation | Required result |
| --- | --- | --- |
| 1–4 | Claim pending initialization; author an actual fresh checkpoint using the original fixture author; inspect; activate; read current controller | Pending inspection has no current controller; explicit normal activation succeeds |
| 5 | Require continuity before any receipt exists | Exit 1, unchanged fixture/ref snapshot; refusal retained as a constructed deterministic abnormality |
| 6–9 | Declare the genuine fresh fixture `new-session`; separately read STATE then ROADMAP; resume G0001; verify and require | Exact new receipt verifies and is returned by currentness |
| 10–12 | Declare a deliberate `manual-resume`; use currentness to gate a harmless file effect; verify old receipt | Both stale checks exit 1; the effect is actually withheld; fixture snapshots are unchanged by the read-only checks |
| 13–16 | Author the fixture's G0002 reconciliation; separately read STATE and ROADMAP; resume; verify; gate the harmless effect; reject predecessor again | Distinct new receipt passes; only the current receipt admits the fixture effect; old receipt still refuses |

The fresh-session and manual-boundary records are honest fixture events, never
claims that a physical host compaction or Stop occurred. The driver preserves
the two controlled abnormalities in the fixture Andon table. It leaves the task
and audit object open. The final result records successful helper operations
outside the receipt-bound STATE rather than rewriting that state after receipt
issuance. Thus historical Andon table entries remain open in the final fixture;
this source run does not declare an audit closed or retroactively emit L4 model
judgment. Root can receive the literal helper scopes independently.

Every normally completed command retains its stdout, stderr, observed exit status
and timing. A timeout first saves its originating error and available output in
separate `*.timeout.*` files, before attempting one SIGKILL to the process group
created for that command. A second communication has a ten-second bound; signal
or drain failures are retained as secondary errors. The final command record is
written even after those failures, with partial or unknown captures, an explicit
unknown exit when necessary, and a failed-timeout status. A sent signal alone is
not reported as observed termination. Missing output remains unknown, and a
completed drain cannot turn the original timeout into success. Evidence writes
still depend on a functioning filesystem; abrupt host loss can leave an intent
or timeout snapshot without a final record.

Read-only helper checks compare the entire bounded fixture file/ref population
before and after. Each command has a 60-second initial window and at most one
ten-second cleanup communication. No broader signal, retry or unbounded wait is
used. If termination cannot be observed, remaining owned processes are left to
the hosted job/VM lifecycle and the result remains incomplete. The job has a
separate 15-minute ceiling. No automatic retry exists.

## Result custody and cleanup

The artifact name is `dg17-exact-a297-host-<run_id>-1`; `overwrite: false` retains
one immutable provider artifact. `RESULT_INVENTORY.json` binds the result files
and raw command captures. It excludes itself, avoiding a self-referential hash.
The two constructed hidden custody records, `.claimed` and `.controller`, are
retained as ordinary `custody-records/claimed.txt` and `controller.txt` files;
`FIXTURE_FILE_MAP.json` preserves their original fixture names and exact hashes.
Unexpected hidden records refuse. This keeps hidden-file upload disabled while
retaining the complete selected fixture evidence.
The upload action's separate archive digest binds the complete final archive.
Prepared source and fixture paths are disposable job resources, not a real-home
installation. An interrupted job can leave partial owned paths until its hosted
VM is discarded; absence of a terminal result remains incomplete evidence.

Root may retain/publish the received evidence additively from the current results
head under its separate authority. The qualification branch does not replace
Root's integration checkout and does not reset earlier findings or acceptance.
