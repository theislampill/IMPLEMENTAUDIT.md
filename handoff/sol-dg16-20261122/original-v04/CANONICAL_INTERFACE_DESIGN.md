# DG16 V02 and V04 canonical interface design

**Hold canonical execution at the first missing owner edge.** The existing canonical qualifier accepts an operation mode and output directory. Its normal route receives no live completion frontier or task lease before dispatch. The two existing owners that do issue live completion frontiers select different tasks and have no entitlement to import an interrupted canonical verifier result. The proposed interface below is a source-only design. The earliest missing edge is **before canonical launch**. None of these normal callers both owns an issued verifier TASK and selects the intended canonical completion receiver for that TASK. Existing direct CLI capture, actual M2 receiving, portable V04 evidence and fixed C5 stages retain separate scopes. A task envelope drafted after the verifier returns cannot fill the gap.

## Opt-in contract for a future owner-selected successor

A future admitted parent issues and keeps custody of one verifier TASK before launch. Its issue binds the actual occurrence, route, exact dispatch and graph, declared inputs, applicable checker and candidate, consuming JOIN and expected journal lineage. The capture owner receives a handle bound to that issue and closes current readback before its observation is consumed. The owner also verifies actual process identity and that launch followed release. An exact artifact digest alone is insufficient to authorize settlement.

**V02 property attachment.** The checker owners publish the exact property population and input/normalization contracts. A new attachment binds each property exactly once to the actual node or composed prelude occurrence, ordered command role, checker and input descriptors, observed toolchain/environment, writer/resource, raw output location, evidence ceiling and invalidators. Receipt compares the observed property population to the declared population. An inapplicable rule, an unexecuted rule and a passed rule retain separate results. The registry's no-tests and register-once failures can occur before a valid graph; a pre-graph refusal carries its own scope and cannot become a normal node observation. The three existing registry observations and the two locally isolated prelude blocks remain partial evidence. No complete mapping can be inferred from the 119-node census. [Portable property evidence](../original-v02/PROSPECTIVE_PROPERTY_CAPTURE.md) · [Current prelude evidence](../original-v02/PRELUDE_VERSION_PROPERTIES.md)

**V04 occurrence and settlement attachment.** Independently bind the qualifier's retained capture to the same open issue and validate it through the existing retained-record owner. Keep signed process exit and wrapper exit distinct, preserve legacy's absent node trace, and preserve the DAG's source-ordered started/failed or interrupted prefix and unsettled suffix. The task owner creates the existing typed result from that actual observation under the original frontier and current expected-old lineage. The reducer can settle a terminal interrupted task without accepting the JOIN or releasing the successor. Unknown process completion or a missing mandatory observation holds settlement. This attachment cannot turn an unexecuted verifier slot into a settled result. [Exact trace reducer](https://github.com/theislampill/IMPLEMENTAUDIT.md/blob/51416b2f156b341c4a5f09029e2c6ceb5b30b1e7/scripts/qualify-work-graph-verifier.py#L722-L761) · [Peer-received portable dispatch control](VERIFIER_DISPATCH_ASSOCIATION_HOLD.md)

## Compatibility and first receiving decision

Version both attachments explicitly in a new opt-in successor entry and closed receiving contract. Keep any new envelope outside the current sealed capture population. Freeze the existing CLI modes, result v1–v4 and correspondence v1 encodings, current retention plan, existing work-result v1 and required JOIN semantics, and every current C5 tuple. Absence of the opt-in keeps current callers' acceptance and capture rules. An old reader never infers the added observations or admits an unknown schema. Both exact product lineages pin the existing qualifier through the R5 inner-capture tuple. Neither an altered qualifier nor a new attachment can inherit that tuple's authority. [Frozen source pin](https://github.com/theislampill/IMPLEMENTAUDIT.md/blob/51416b2f156b341c4a5f09029e2c6ceb5b30b1e7/scripts/load-work-graph-c5-executor.py#L162-L173)

First require the actual task issuer and completion consumer to name their existing scope and the supported verifier route they can own from dispatch through retention. The later evidence must be the same authorized occurrence: complete declared property receiving for V02 and actual interrupted/no-success settlement for V04, with stale, foreign, missing, duplicate and falsely settled cases rejected at their applicable boundaries. Preserve current output/diagnostic limits and earlier receipts. Another portable or hosted replay, a post-hoc attachment, or invoking the singleton observer offers no evidence for this missing owner edge. Implementation, canonical execution and original awards remain held.
