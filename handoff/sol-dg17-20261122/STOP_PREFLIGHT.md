## Why this route

An inert run of the isolated output formatter confirmed two distinct preimages.

| Route | Exact observed wire outcome | Host ceiling |
|---|---|---|
| Generic no-argument unbound | Its diagnostic object carries seven unrecognized Stop output fields. | The pinned host schema is closed. Host source marks invalid JSON schema output as a failed hook. An otherwise completed turn supplies no qualifying result for this route. |
| Selected policy, ordinary thread absent from the selection | The formatter emits `{}\n`. The closed schema allows this JSON object. | The host's Stop parser treats a parsed output without a block/stop disposition as completion. A live capture must still prove that the trusted handler actually ran and its event was consumed. |

The proposed route uses the selected policy's early return before ingress writes, binding lookup, or validator selection. The valid native event is a host-generated JSON object with session and turn IDs, Stop name, working directory, active flag, last-assistant message, model, permission mode, and transcript path. The code checks isolated Python flags and captures exact policy bytes by digest before comparing session ID. The frozen all-zero sentinel selects no real thread. A fresh host ID unequal to the sentinel is a before-turn guard. No generated package files or Stop patch are needed for this scope. [Exact input schema](https://github.com/openai/codex/blob/3d2ee51ca2d5db578f328aa75e20aa22c0197c9a/codex-rs/hooks/schema/generated/stop.command.input.schema.json), [output schema](https://github.com/openai/codex/blob/3d2ee51ca2d5db578f328aa75e20aa22c0197c9a/codex-rs/hooks/schema/generated/stop.command.output.schema.json), [host parser and result classification](https://github.com/openai/codex/blob/3d2ee51ca2d5db578f328aa75e20aa22c0197c9a/codex-rs/hooks/src/events/stop.rs).

A matched session would instead need the exact policy/cwd, an external evidence directory, pinned binding owner and selected matching binding, run root, disposition, pinned lifecycle validator and Windows custody. A valid yield is therefore a different operation with unmet live selection prerequisites. The prepared no-task route does not cross them. [Selected contract](https://github.com/theislampill/IMPLEMENTAUDIT.md/blob/51416b2f156b341c4a5f09029e2c6ceb5b30b1e7/skills/implementaudit/scripts/host-stop-interlock.py#L417).

## How a later authorized operation could be received

1. Root names the operator and separate receiver. Bind the actual disposable home, empty working root and exact isolated paths/config to the packet. The owner must approve the one scoped service turn and review the sole synchronous Stop command through Codex's trust mechanism. `hooks/list` must show the expected key, path and current hash as trusted and enabled. A config edit or process exit alone cannot supply this observation. [Codex hook trust](https://learn.chatgpt.com/docs/hooks#plugin-bundled-hooks).
2. Use one owned raw app-server connection and its experimental API schemas. A proposed `thread/start` uses an ephemeral thread, read-only sandbox, no approvals or inherited optional integrations, and the exact isolated working directory. Bind the host-returned thread identity and effective model, provider, reasoning effort and permissions before the sole `turn/start`. This host-only stimulus adds no model-quality credit. Preserve actual provider revision as unknown if the host cannot authenticate it. [App-server protocol](https://learn.chatgpt.com/docs/app-server).
3. Require a same-thread, same-turn `hook/started` and `hook/completed` for the same known run ID, event `stop`, command and synchronous mode. The native completion must report `completed` with no failure or continuation feedback. Require subsequent same-turn `turn/completed` and no hook-triggered extension before it. Read back the exact hook/config and absence of effects in the isolated scope. The relevant host parser classifies invalid output as failed, blocking output as blocked, and valid no-block output as completed. This joins actual event consumption and normal turn end. The selected no-task path leaves no direct raw adapter ingress body. The receiver must retain the actual RPC frames and apply the stated ceiling. In this release `codex exec --json` ignores the two hook notifications, so its output alone is insufficient. [Native hook events](https://github.com/openai/codex/blob/3d2ee51ca2d5db578f328aa75e20aa22c0197c9a/codex-rs/app-server-protocol/src/protocol/v2/hook.rs), [CLI JSONL event processing](https://github.com/openai/codex/blob/3d2ee51ca2d5db578f328aa75e20aa22c0197c9a/codex-rs/exec/src/event_processor_with_jsonl_output.rs).

The missing prerequisites are the actual isolated trusted-handler readback, authorized provider/model access and a separate grant for the one exact turn. A skipped hook, missing or ambiguous native event, model reroute outside scope, error, unexpected continuation, or timeout leaves this attempt unqualified. The generic default-installed path requires a separate wire decision. No real settings, app server, hook, login, model, or native session were used in this preflight.
