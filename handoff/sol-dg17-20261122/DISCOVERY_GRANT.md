## Conditional guest-only alternative

The host reports Windows Sandbox feature state `1`, its executables exist, and the hypervisor is present. Microsoft documents guest network disablement through `Networking=Disable`. A fresh, credential-free Windows Sandbox guest would separate discovery from the actual workstation profile and avoid a lasting host firewall or trust edit. The route remains conditional on separately approving guest scope and binding the actual guest network fence before startup. It supplies a guest observation only. It cannot certify the actual workstation profile or absence of any attempted in-guest socket syscall. [Windows Sandbox configuration](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-configure-using-wsb-file#networking).

Map only the read-only input and private output subdirectories. Disable networking and remapping features as specified. Use a fresh guest home and empty working directory under `C:\DG17\run`. Copy only the pinned profile into that home. The pinned Python and adapter paths appear in the hook definition for lookup only. Discovery does not launch them.

Root's one owned stdio process exchanges `initialize`, `initialized` and `hooks/list` for the exact working directory. Only those messages are admitted.
