# Helper reachability fixture map

The focused test creates disposable candidate copies from these deterministic case definitions:

| Case | Expected result |
|---|---|
| each current projection's executable package members equal its full-path declarations | PASS N/N |
| one shipped helper lacks a declaration | FAIL |
| a helper cites only itself as its owner | FAIL |
| a required-procedural owner does not contain the exact helper route | FAIL |
| a declaration uses a non-contract class such as `unit-tested` | FAIL |
| an automatic helper names a missing caller | FAIL |
| an advisory helper claims a mandatory closure effect | FAIL |
| an executable Python, shell or nested member is added without a declaration | FAIL, proving a derived denominator |
| an unknown-suffix or extensionless executable is added | UNKNOWN_EXECUTABLE_TYPE, never omitted |
| one classified member is replaced by an unclassified member at the same count | FAIL by identity |
| a fixture member and its valid row are added or removed together | PASS N+1 or N-1 |
| canonical/standalone executable sets or classifications diverge | FAIL |
| candidate substitutes its checker, package owner or repinned expectations | FAIL; invocation-root authority remains selected |
| governor's typed resolver command is missing, echoed or malformed | FAIL |
| documented resolver/diagnostic commands execute on both projected layouts | bounded source-route proof, not installed event proof |
| a declaration names a helper absent from the package | FAIL |

Package presence, a self-usage comment, direct unit tests, and wildcard discovery are deliberately insufficient dispatch evidence.
The live positive also requires one audit object and a cheap no-event path.
