## Normative turn-yield and binding contract

A bound active object requires one actual admitted disposition: `TERMINAL_CLOSURE`, `AUDITED_HANDOFF`, or `NONTERMINAL_YIELD`. A terminal/handoff claim must be checked by its own predicate; it cannot escape through yield. Conflicting closure and handoff claims are invalid. Ordinary unbound work takes the immediate no-active-object cheap path. Host-forced termination is neither closure nor handoff.

The portable yield mode adds no lifecycle state or audit object. It reads the existing run-root owners: selected STATE/ROADMAP, Current phase, audit-object status, applicable Andon/pause record and selected phase specification. A valid record requires all eleven original common facts: applicable structure; one allowed nonterminal status; explicitly open object; identifiable frontier; latest safe Last check or exact not-yet-run intake reason; concrete Next action; relevant current owner/source/authorization; durable dependency/blocker/decision; re-entry/next probe; no completion marker; no handoff marker unless checking the handoff route instead.

Allowed existing statuses are `open`, `READY_TO_DISPATCH`, `IN_PHASE`, `PAUSED`, `BLOCKED`, `INTERRUPTED`. IN_PHASE requires checkpoint/last safe step/next action; PAUSED requires reason/resume point and the existing user-interruption pause fields when applicable; BLOCKED requires blocker/owner/containment/next probe; INTERRUPTED requires exact owner stop/interruption point/durable log; open/READY requires the actual unresolved intake/dispatch decision and next action. An external wait may be PAUSED or BLOCKED but cannot lose its dependency, last evidence, containment and probe facts.
