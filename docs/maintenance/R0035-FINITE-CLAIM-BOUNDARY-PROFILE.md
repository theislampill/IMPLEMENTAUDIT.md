# R0035 original96: fixed private claim-boundary overlay

This increment adds the explicit `claim-boundary` mode for canonical node 96,
`bash tests/claim-boundary-proof-levels.test.sh`. It is an ordinary finite source
profile, with no canonical, controller, native-host, release or closure authority.
Source qualification and a constructed source-control result do not establish
actual original execution. The two separately gated receiving controls preserve
actual raw failure and never replace it with a predicted result.

## Descriptor custody and actual effect observation

The qualifier creates a fixed 4 MiB census memfd sealed against growing or
shrinking. The bootstrap retains it, closes every other inherited descriptor
above stderr and marks the census fd noninheritable. The actual unchanged Bash
original is launched with `close_fds=True`; it receives no census fd. The
bootstrap does not supply or substitute any checker output.

Before launch, the bootstrap physically censuses all docs and private `/tmp`
entries with no-follow ordinary-file/directory descriptors, bounded populations,
paths and file reads. It records SHA-256, bytes, modes, link counts and actual
filesystem read-only flags. It also checks every immutable source path and `/`
for the real read-only mount flag. The baseline must match the derived captured
image exactly, the two private parents must be writable, and `/tmp` must be empty.
It then records that the original started, waits for its actual exit, and takes
the after census. Actual exits, including signals and shell exit 141, remain raw.
A bootstrap error after the child exits preserves that actual exit; the qualifier
refuses a successful receipt unless the complete after observation is valid.

These are **before/after state censuses, not a temporal write journal**. The
four transient probe writes are known from pinned original source, not claimed
as individually observed syscall events. On success, every protected member
must still match and the private namespace must return to its baseline. New
leftover names, altered protected contents/modes, a missing phase, malformed
record or failed mount check prevents successful reuse. Nonzero original
results remain failures even when cleanup is complete.

The fixed-size report stores a length-delimited JSON payload with the length
committed last. Missing/interrupted records are retained as unobserved or
partial; no after state is inferred. After the namespace ends, the qualifier
seals writes, retains the complete raw buffer plus decoded `source-effects.json`,
and binds those bytes to its existing live-producer receipt/currentness checks.
The original never receives authority from the effect record.

## Conservative source-dependent reservation

Diagnostic allocation considers every necessary anchor in every applicable
current public read population, all rule-family overlaps and Unicode line
splitting. Replacement decoding is used only to overcount allocation; the
original's decoding, exemptions and acceptance logic are untouched. Fixed and
strict-decoder margins cover direct reads, portal matches, probe diagnostics and
wrapper failures. Only the six strict direct Python reads receive the decoder margin; both
recursive read loops catch decoding errors and skip the member. The full current
source data and path population also bound Python data memory and census/configuration size. Excessive diagnostics,
materialized file size, complete image/descriptors, original data memory,
configuration or private names refuse before dispatch.

With a 64 KiB allocation granule, the docs reservation is
`(existing immediate docs entries + 3) * 65536`, covering the root, existing
mountpoints, one new inode and its rounded fixed probe payload, inside the
1 MiB quota. Private `/tmp` reserves the rounded diagnostic plus one rounded
checker spool and three metadata granules; the five checker calls are synchronous
and close each spool before the next call. The one diagnostic is overwritten
twice and retained during the two later checker calls. The total scratch reservation adds
the full 1 MiB docs quota. Python data memory allows eight wide Unicode buffers plus two raw buffers
(34 times the largest read file), 128 bytes per line in the largest simultaneous
line population, diagnostic/join/encoding buffers, direct-read tokenization,
portal owners/mutations, paths and startup. It keeps the existing quarter-address
image reservation and refuses excess before runtime capture. The 4 MiB observer buffer is charged to memory and
file/descriptor bounds, not silently added to the writable source quota.
