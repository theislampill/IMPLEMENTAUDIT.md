# R0035 finite audit retention profile

`audit-retention` selects original verifier index 58,
`COMMAND:tests/audit-retention.test.sh:0`, through the existing live finite
session and isolated-leaf executor. The registry still contains 117 original
nodes. The command remains exactly `bash tests/audit-retention.test.sh`.
Neither checker source nor any of its four calls is rewritten. The original
three negative fixtures and their specific diagnostics remain part of that
single command.

This is a source and acquisition increment. Original-command qualification
requires separately allocated receiving execution. It creates no canonical
117-node composition, native authority, host or combined-cap claim. The
original 48 requirements, 20 cases, 117 nodes and eight raw RED controls keep
their existing boundaries. Ordinary serial execution remains available when
this deliberately bounded profile refuses a source.

## Complete input and genuine Git custody

The default checker always attempts the actual `git ls-files -z`. Its broad
exception branch traverses the whole source root. Its active-file predicate
also contains empty prefixes, so every selected ordinary file survives that
predicate before the explicit archive/history/changelog/fixture exclusions.
The finite acquisition therefore captures the entire actual source, including
research, every other fixture, tests, skills, registry and runner bytes. It
also captures the entire genuine Git namespace, including packed and loose
objects, the index, config, refs, logs, names, file types and empty directories.
The fallback traversal receives those same complete actual names and bytes.
Nothing is sourced from a projected HEAD tree or a synthetic Git answer.

The existing C2 preflight owner now accepts an internal fixed finite request.
Its old argument-free behavior remains unchanged. The new request is limited
to a real standalone Git directory whose source root and Git directory are
owned by the actual producer. Git discovery HEAD, objects and refs directories
are observed physically. Only a SHA-1 version-2 index with ordinary stage-zero
regular entries and an optional TREE extension is supported. Split indexes,
assume-valid/extended/staged entries, symlinks, unknown extensions, external
storage, worktrees, partial clones and unsupported config refuse before the
original command. The existing prefix namespace and config rules remain the
owner of those refusals.

The closed startup environment adds `HOME=/nonexistent` and
`GIT_ATTR_NOSYSTEM=1` only for this profile. Actual selected config/control
bytes and user-control absences are observed, retained and rechecked. No
`safe.directory` override is injected. The existing C2 owner runs its real,
bounded read-only Git observation and verifies its ordinary-index population;
the original checker later performs its own unmodified Git call from the
captured bytes. The C2 output is retained as admission evidence and is never
supplied to the original program.

The actual selected `/usr/bin/git` physical identity and bytes must match the
existing acquired runtime. The complete source closes before and after that
observation and again at session acquisition boundaries. The isolated image
contains the original registry and runner as readable data; the runner's bytes
must also equal the captured launcher before its executable image mode is
selected. Every existing runtime, custody, currentness and no-reuse check
continues to apply.

A missing Git directory and a linked Git marker are explicit unsupported
source states for this increment. Removing a present Git marker to induce the
fallback is not an eligible transformation. Supporting ancestor discovery or
external/linked Git storage remains separate C2 work. This restriction does
not change other finite profiles' independently bounded no-Git contracts.

## Fixed bounds and complete effects

| Resource | Fixed audit-retention bound |
|---|---:|
| Each captured source member | 16 MiB |
| Complete source including Git | 192 MiB |
| Files and directories combined | 4,096 |
| Namespace depth | 40 |
| Each UTF-8 relative path | 2,048 bytes |
| Each materialized image member, including runtime | 16 MiB |
| Complete image memory reservation | 256 MiB |
| Descriptors including existing launch and observer margin | 4,096 |
| Complete bubblewrap argument vector, including outer arguments | 8,500 |
| Private scratch | 32 MiB, unchanged |
| Original process address limit | 1 GiB, unchanged |

All executable limits are inherited unchanged. In particular, the existing
launcher applies its 16 MiB file limit while bubblewrap materializes each
sealed member. A source member larger than that cannot be admitted merely
because the total image fits. Admission checks every image member explicitly.
An owned standalone clone may be losslessly repacked before acquisition; its
actual resulting pack sizes and complete namespace then govern admission.
Repacking does not assert that an arbitrary input clone fits the bound.

The wrapper retains three fixed diagnostic files and one generated private
file in one temporary directory. Allocation also charges all four checker
heredoc spools and the wrapper heredoc spool simultaneously, with a 64 KiB
allocation granule and per-entry overhead. The original checker can accumulate
many diagnostics: bounds use complete actual selected/fallback names, archive
basenames and necessary raw reference anchors while ignoring semantic
exemptions. These calculations allocate space; the original checker alone
decides semantic success. Output, scratch and per-file bounds each refuse
independently.

The remaining three quarters of the unchanged address limit reserve source
decoding, diagnostic accumulation/joining, line splitting, Git stdout and
path/name containers. A complete image or derived data reservation that does
not fit refuses. No public option raises these limits. The only mutable
resources remain private bounded scratch, the existing null device and the
observer streams. This profile neither adds proc nor imports host-root files.

The first receiving attempt retained a genuine launcher failure:
`bwrap: Exceeded maximum number of arguments 9000`. Its complete image had
2,195 members and required 12,594 arguments; passing them through `--args`
does not avoid bubblewrap's parser limit. The original checker had not
started, and no success, reuse or dependent negative control was inferred.

For this fixed profile, non-executable image members now have mode 0600,
the default of `--ro-bind-data`, behind the same per-file read-only mounts.
The image records every effective mode and the explicit
`OWNER_0600_READ_ONLY_MOUNT` policy. Captured source modes and physical
identities remain in the source observation; executable image members retain
0555. This is an explicit normalization of image permissions, not a claim
that they equal source permissions. Owner write permission bits do not permit
writes through the read-only mounts. The final root remount remains read-only.
Existing finite profiles retain their own image policies.

The existing launcher omits only the redundant 0600 data mode arguments and
retains explicit 0755 directory creation. It retains every sealed member,
including empty directory observations. It counts the complete argument vector
before dispatch and refuses above 8,500, closing all descriptors. A larger
future population must qualify another bounded representation; it cannot drop
inputs, relax the namespace or silently retry a weaker launcher.

## Finite controls and receiving

`tests/work-graph-audit-retention-cases.py` contains the new source controls.
They use small genuine private Git repositories and the real existing C2
observer; source-admission tripwires prevent original execution. They cover
the complete namespace, explicit unsupported layouts/config/index states,
currentness, original program pins, physical Git/runtime binding, source and
image member ceilings, memory, descriptors, streams and scratch. The wrapper
bank and its independent ordered environment-capture oracle both include the
new file. The existing entry protocol and fixed-loader tests remain separate
from original-command qualification.

The two live controls are gated by
`R0035_FINITE_AUDIT_RETENTION_LIVE=1`. A receiver may select its complete genuine
owned source with `R0035_FINITE_AUDIT_RETENTION_SOURCE`; otherwise the test
copies the whole current repository. Every actual file and directory,
including Git, is copied. Unsupported storage is preserved and refused.
The positive control requires the original success output, two run requests,
one dispatch and the exact retained receipt/key. The negative control changes
one acquired policy token, requires the original diagnostic, and verifies that
the failure never becomes reusable. Each receiving session has fresh custody;
stored evidence is never an imported live result.

The public interface is the existing two-path protocol:

```sh
printf '%s\n' '{"operation":"run"}' '{"operation":"run"}' |
  /usr/bin/python3 -B scripts/qualify-work-graph-verifier.py audit-retention \
    /absolute/complete-owned-source /absolute/new-evidence
```

Run that interface only under the independently allocated receiving lane.
The source-only authoring controls do not establish an original58 result.
