### Protected effect

The fence is conditional on the existing run's selected fence carrier or the
explicit `--require-generation-fence` requirement. It binds the request,
controller, current receipt, generation and target preimage. The helper reads
one bounded regular-file buffer and rejects malformed, aliased, replaced,
late-appearing or missing-required evidence without downgrading the route.
It uses the canonical claim owner to verify continuity rather than parsing a
second receipt schema.

A verify-only native Git prepared reference transaction holds the current
authority refs, migration marker, generation pointer, invalidation, receipt
and HEAD/current branch against cooperating publication during target effects.
Git reference-transaction hooks are suppressed for this internal verification
transaction using command-local configuration. The existing namespace gate
and mutation journal remain the owners of local serialization and recovery.
Target and rollback effects end and their terminal journal is durable before
the reference guard is released. Guard loss or uncertain release preserves
`UNKNOWN`, manual reconciliation, retained evidence and no automatic retry.
Actual auxiliary Git lock/directory effects are recorded, including unresolved
residue. No authority ref is updated by the verification guard.

The original fixed v2 result, authority and journal contracts remain unchanged
for ordinary work. Protected records explicitly use v3. Full-suite integration
exposed the original unversioned extension; its failing consumer and new early
refusal/late-carrier witnesses are retained. The repair versions those records
at the same mutation owner without relaxing the original v2 consumer.

The guarantee is limited to governed helper-routed cooperating writers and the
qualified Git files backend. It does not fence an arbitrary same-principal
writer, create an authentic host principal, supply external API idempotency or
prove consensus, universal availability or a complete distributed runtime.
