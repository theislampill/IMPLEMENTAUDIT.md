## Receiving contract

The public Python factory is
`create_finite_leaf_session(source_root, output, profile=..., max_age=3600)`.
Its default is the audit-spec profile. Unknown profile values refuse before an
evidence directory is created. Each session has its own live producer identity,
private evidence root and issued-result store. A cached session class is not a
shared result cache.

The factory captures the finite helper's bytes once and executes that exact
buffer. The helper captures and pins its existing prefix dependency. Session
construction and every consumption revalidate those captured bytes against the
physical current engine files. A changed helper, foreign path alias, changed
producer process or changed retained evidence cannot turn a prior result into a
current one.

Each CLI mode takes the actual source root and a fresh external evidence path.
For example, on the supported Linux runtime:

```bash
printf '%s\n' '{"operation":"run"}' '{"operation":"run"}' |
  /usr/bin/python3 -B scripts/qualify-work-graph-verifier.py audit-spec \
    /absolute/source /absolute/fresh-evidence
```

Each line is at most 4,096 bytes and must decode to exactly
`{"operation":"run"}`. Duplicate keys, supplied receipts, program strings,
claimed exits, environments, reuse plans and alternative operations refuse.
The first successful request executes the original acquired command; a later
unchanged request may reuse only that live producer's revalidated result.
Incomplete or signal-terminated results map to a nonzero CLI status and earn no
successful reuse. Full-capture options are unavailable on these routes.

The finite helper's original source closures, exact executable pins, private
scratch bounds and independent-node limits are documented in
`R0035-FINITE-LEAF.md`, `R0035-AUDIT-SPEC.md` and `R0035-ANDON-CLASS.md`.
No omitted predecessor effect is supplied and no private test output is exported
to a successor. The separate README effect contract, when qualified, owns its
own physical producer/consumer evidence.

## Verification and evidence limits

`tests/work-graph-finite-entry-cases.py` checks the receiving factory, private
custody and bounded protocol. Its protocol-routing doubles are explicitly unit
controls and are not original-command execution evidence. The component's
actual-command tests and an independent final-engine CLI run supply that separate
evidence. The canonical verifier wrapper registers the three component banks
and the entry controls; its exact child census continues to check capture-variable
stripping and preservation of unrelated environment values.

A receiving review must bind the final qualifier/compiler/helper bytes, execute
the four real original commands, and verify unchanged second requests retain the
same receipt with one dispatch each. Earlier component observations on different
engine bytes remain historical evidence, never relabeled as a final-source run.

These four independent profiles may expand the separately demonstrated finite
union only at their actual reviewed source. They do not prove full canonical
chain equivalence, general accepted JOIN, authentic native task admission,
Windows execution, prefix24 namespace availability or the original whole-issue
acceptance. All eight historical raw-comparator REDs remain unchanged.
