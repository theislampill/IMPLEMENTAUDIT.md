Formal Methods & Verification Engineering

Use this lineage to state the protected property precisely, expose assumptions, and choose a check whose result actually bears on that property.

What this lineage contributes

Formal Methods & Verification Engineering starts with a precise property, then contributes explicit assumptions, invariants, temporal properties, abstraction and compositional contracts. It distinguishes safety from liveness, local checks from system claims, and tool success from a proof about the intended environment.

A proof or deterministic checker is useful only while its property, model, toolchain, inputs and configuration remain current. The proof currentness boundary is therefore part of the claim, not a later administrative detail.

What changed

The landed v0.4.0 composition strengthens evaluator discipline and exact-identity release checks. When a candidate and its evaluator both change, retained witnesses, old/new product-by-evaluator comparisons and held-out positive, negative, boundary and adjacent cases prevent self-authenticating green.

Cross-family release verification now requires the named candidate commit itself; a different same-tree commit cannot satisfy that identity contract.

What was already native

IMPLEMENTAUDIT already required explicit invariants, terminal markers, exact hashes, deterministic package checks, negative evidence and independent review. Many formal properties therefore mapped to existing stronger or equivalent native controls.

What was rejected

No universal formalisation, theorem-prover requirement, proof-count target or ceremony around notation was adopted. A model is not required where a direct authoritative discriminator is cheaper and sufficient. Formal appearance cannot rescue the wrong property.

What remains unverified

This route does not claim that IMPLEMENTAUDIT is formally verified, that its environment model is complete, or that all safety and liveness properties have mechanical proofs. Toolchain soundness and external-host behaviour remain separate evidence obligations.

Provenance
