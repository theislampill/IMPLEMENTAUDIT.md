Package boundary

The primary release/install unit is one atomic dual-host plugin. IMPLEMENTAUDIT.plugin.zip preserves both host manifests, package/inventory metadata, the public/default /implementaudit governor, and exactly four child skills: audit-state, audit-assess, maintainer-only audit-implement, and dual-entry audit-andon. References, templates, and helper scripts remain shared governor substrate; planning and execution/repair remain progressively loaded references.

IMPLEMENTAUDIT.skill is generated and checksummed from the same source as a standalone compatibility artifact. It flattens the governor runtime tree to archive-root SKILL.md, references/, scripts/, and templates/, adds deterministic internal-procedure projections, and retains package/inventory metadata. It does not expose independent child packages and is not the canonical topology or an independently versioned package.

Repo-only docs, fixtures, tests, local run roots, sidecar stores, and generated docs are in neither runtime projection.

Source surfaces

AGENTS.md is the concise maintainer bootloader, CONTRIBUTING.md owns the current contribution workflow, and README.md is the new-user public entry.
skills/implementaudit/ owns runtime behavior; package/implementaudit-package.json owns package topology; CHANGELOG.md owns release chronology; release reports own exact qualification and publication evidence.

Contributor route

Read the current contributor guide before changing runtime, package, public-doc, validation, or release owners.
It records source-versus-generated ownership, platform requirements, focused-to-complete validation, registry and helper reachability rules, and the independent authority gates for commits, pull requests, issues, tags, releases, and publication.

Docs portal generation

The portal is generator-owned.
Edit docs/portal/, then regenerate generated output instead of hand-editing dist/.

  • scripts/build-docs-portal.py builds the portal from source pages, shared assets, and site.json.
  • scripts/check-docs-portal.py validates routes, anchors, metadata, and generated shell behavior.
  • scripts/verify-docs-portal.sh runs build plus validation as the narrow docs gate.
  • GitHub Pages or any published docs update remains a separate owner-authorized action.
