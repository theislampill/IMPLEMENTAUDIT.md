Installation

The normal release/install unit is one atomic dual-host plugin package.
Package shape, staged copy, native host loading, and audit correctness remain separate evidence.

The published v0.4.0.0 URLs below were independently downloaded and matched to the frozen release identities. The runtime version is 0.4.0. IMPLEMENTAUDIT.plugin.zip is the canonical generated projection; IMPLEMENTAUDIT.skill is a generated, checksummed standalone compatibility projection. Public asset integrity and isolated copy/install readback do not prove native host loading, marketplace state or provenance.

Skills CLI path

The repository is discoverable through the open skills CLI directory. Install from the current repository source with:

Skills CLIsource
$ npx --yes skills add theislampill/IMPLEMENTAUDIT.md

This route follows the repository's current source and may expose the public governor plus its four child skills to a capable host. Invoke /implementaudit; discovery is not routing or authority. audit-state, audit-assess, and audit-implement refuse direct entry; an explicit audit-andon cord-pull returns bounded cognition to its caller without new authority. This route is distinct from the canonical plugin release artifact and from a checksum-verified GitHub release asset. It does not prove refresh behavior, auto-update, marketplace verification, release-byte identity, or host loading.

Canonical dual-host plugin path

Use the host's current native plugin installation route with IMPLEMENTAUDIT.plugin.zip, then verify that the expected host discovers /implementaudit at version 0.4.0. The atomic package carries equal Codex and Claude manifests, package/inventory metadata, one skills/implementaudit/ governor with shared references/templates/scripts, and exactly four child skills: audit-state, audit-assess, maintainer-only audit-implement, and dual-entry audit-andon.

The repository helper below is intentionally limited to isolated staged-copy, update, rollback, inventory, and readback proof. The target must be a disposable directory containing .implementaudit-isolated-host-root; it is not a native host install command:

Canonical plugin staged copylocal evidence
$ bash scripts/install-plugin-from-release.sh \
  --asset dist/IMPLEMENTAUDIT.plugin.zip \
  --checksum dist/CHECKSUMS.txt \
  --host codex \
  --host-root "<isolated-host-root>" \
  --version 0.4.0

Repeat with --host claude for the separate staged Claude projection check. Passing either route does not establish native discovery, invocation, marketplace behavior, publication, or public-download identity.

Verification boundary

Install evidence has levels:

  • Source validation checks the package contract, manifests, and exact v0.4 skill population.
  • Archive-shape validation checks the canonical plugin or standalone compatibility projection.
  • A checksum match verifies each named asset against the manifest when supplied.
  • Staged plugin copy or a copied standalone skill folder proves only the files and post-state that were checked.
  • Only the host can prove the skill loaded.
  • Keep those claims separate when debugging.

Re-check before claiming release status:

  • The release tag exists.
  • Both declared assets can be read.
  • CHECKSUMS.txt verifies the named IMPLEMENTAUDIT.plugin.zip and IMPLEMENTAUDIT.skill bytes when supplied; the v0.4.0.0 release-page, checksum and fresh-download digests have independent readback in the release report.
  • Pages is current only after deploy success.
  • Local installs do not auto-update.

Updating later

This repo does not claim passive host updating.
Reinstall or refresh the canonical plugin using the host's documented update path, or repeat the standalone compatibility copy when that route is required. Then rerun a small repo request and check the visible version and closure markers.

Claude Desktop users should restart Claude Desktop after a copied skill update and verify the skill inside the host.
Session-managed skill paths can change between Claude Desktop versions; if the path differs, use the host's built-in skill management UI.
