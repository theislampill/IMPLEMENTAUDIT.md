## Portable repository observation

An explicit source-only reader is available before native acquisition. `scan` reads one exact Git worktree and emits a deterministic repository-only snapshot to stdout. `inspect` reads that frozen file. Neither selects a controller/run, creates a native receipt, writes a snapshot directory/CURRENT pointer, or calls the native publisher. There is no automatic or default invocation. The existing native `status`, `query`, `why`, and `export` routes still derive their owner internally and accept no repository, run, epoch, receipt, or snapshot override.

```bash
python -B "$IMPLEMENTAUDIT_REPO_ROOT/scripts/operational-evidence.py" scan "$REPOSITORY" > "$TASK_OUTPUT/repository.json"
python -B "$IMPLEMENTAUDIT_REPO_ROOT/scripts/operational-evidence.py" inspect "$TASK_OUTPUT/repository.json"
python -B "$IMPLEMENTAUDIT_REPO_ROOT/scripts/operational-evidence.py" inspect "$TASK_OUTPUT/repository.json" --family CODE --max-rows 100 --max-bytes 262144
python -B "$IMPLEMENTAUDIT_REPO_ROOT/scripts/operational-evidence.py" inspect "$TASK_OUTPUT/repository.json" --format graph --max-rows 100 --max-bytes 262144
```

The caller chooses an existing isolated `TASK_OUTPUT` directory; shell redirection is caller-owned output, not atomic native publication. For canonical JSON use `inspect <file> --format json`; for retained dependency explanation use `inspect <file> --why <record-id>`. `diff <before> <after>` accepts two snapshots of the same acquisition scope. Frozen inspect/diff/render are offline and run no subprocess, target code, or model. Graph and table formats are inert JSON. Bounded views include an omitted-state census and cannot claim a complete decision when truncated.

`implementaudit-repository-snapshot-v1` and its `iarepo-v1-` identity are distinct from native `iasnap-v1-` snapshots. The input manifest binds the exact repository collection, schema bytes, compiler bytes, checked query-policy bytes and reading profile through canonical SHA-256. Checkout spelling, timestamps, duration, process identity and cache state do not enter the payload. The aggregate is always `DEGRADED`; OWNERSHIP, EXECUTION, EVIDENCE, FAILURE and RELEASE retain an explicit `UNVERIFIED` acquisition census. A matching hash authenticates no native event or source owner. Inspection reports `REPOSITORY_ONLY_UNAUTHENTICATED_FILE`; changing the scope, aggregate, population, producer grammar or hash is a typed refusal. This route cannot satisfy native C03/C06, actual receiving/JOIN, installation, release or whole-issue acceptance.

### Repository input profile

Git reads clear ambient Git selectors/trace configuration and use an isolated read view with bounded, nonfollowing copies of HEAD, index and refs, fixed configuration, and the source object store. Target configuration and hooks are never loaded, including configuration introduced during a command. Optional locks, replacement objects, lazy fetching, external transports, hooks and fsmonitor are disabled. ## Canonical record

`operational-evidence-schema.json` defines `implementaudit-operational-evidence-v1`. Every record preserves exactly one of the frozen `CODE`, `OWNERSHIP`, `EXECUTION`, `EVIDENCE`, `FAILURE`, or `RELEASE` families and binds a native owner, source identity, source layer, evidence layer, and primary currentness state. The loader rejects a source/evidence layer mismatch; a relation may connect entities from different native layers, but its own evidence leg cannot silently borrow another layer's authority.

The primary fact states are `CURRENT`, `UNKNOWN`, `UNSUPPORTED`, `STALE`, `UNVERIFIED`, `CONTRADICTORY`, `PARSER_ERROR`, and `INVALID`. A `CURRENT` record cannot retain an invalidator. A `STALE` record must name at least one invalidator. `COMPLETE` requires one required `CURRENT` entity in every frozen family. Non-complete aggregates name their affected families explicitly, so unsupported, missing, or invalid input never degrades to a silent empty result.

## Byte contracts

`canonical_json_v1` is UTF-8 without BOM, recursively sorted object keys, declared array order, no insignificant whitespace, strict JSON scalars, and no implicit Unicode or line-ending rewrite inside ordinary strings.

For immutable event identity shared with R0039, strict JSON scalars exclude floats and limit integers to signed 64-bit values. The carrier therefore emits the same no-terminal-LF `canonical_json_v1` bytes for an admissible value; only the typed source-locator path contract applies NFC normalization.

Source text payloads have one separate, explicit normalization before canonical JSON serialization:

1. replace CRLF with LF;
2. replace remaining CR with LF;
3. remove every trailing LF;
4. perform no other whitespace or Unicode normalization;
5. encode as UTF-8 without BOM and verify `payload_sha256` over those bytes.

This is the trailing-LF-removed convention used by the R0038 live-object re-anchor. A one-trailing-LF digest is not a competing content fact and is not accepted as the canonical payload digest.

The repository-only carrier is `scripts/operational-evidence.py`. `validate` returns a typed validation receipt and `canonicalize` returns the canonical record bytes. Unsupported schema versions and invalid inputs return one machine-readable `implementaudit-operational-evidence-error-v1` object on standard error with a stable error code; they never return an empty model. C01 does not register this carrier as a shipped helper or public route. That later admission remains C11's owner boundary.

The compiler binds exact compiler and schema bytes, the portable native-current semantic record, controller/claim/run/source epoch/current pointer, hot STATE, ROADMAP and WORK_GRAPH digests, canonical R0033 route identity and every collector result/digest in `implementaudit-operational-snapshot-input.v1`.
