## Scope and central finding

Formal methods contribute precise statements and disciplined ways to reason about them. Their useful outcomes range from finding one counterexample, through proving a bounded result, to establishing a theorem for every execution admitted by a specified semantics. These outcomes have different quantifiers. None becomes an empirical claim about a deployed system merely because it is expressed formally. Conversely, an unresolved deployment relationship does not erase a correct mathematical theorem or a complete result for a finite model. This study retains that distinction throughout the native population of 50 properties.

The strongest surviving contribution is a family of conditional inference practices, not a universal requirement to formalize everything. A local contract can resolve a troublesome interface. Exhaustive enumeration can settle a genuinely small domain. A proof can establish an unbounded statement under explicit hypotheses. A monitor can detect violations on the observations it receives. A compiler theorem can preserve a property across one defined translation boundary. Their value depends on the decision, the semantics, the remaining premises and the cost of producing and maintaining the evidence. The historical critique that formal reasoning can be mistaken for complete real-world assurance remains relevant; it does not establish that narrow, sound results are useless. The 19 author constructions in [the case account](../SOURCE_MAP.md#s-0be00f7164600b45) discriminate these positions without pretending to measure industrial prevalence.

## 2. Genealogy: descent, reaction and resemblance are different edges

This lineage is plural. Assertions and predicate transformers concern reasoning about program behavior. Denotational accounts supply meanings for languages and recursive definitions. Abstract interpretation relates concrete and abstract domains. Temporal and process approaches describe behaviors extending across time and interaction. Type systems and program logics classify or prove different program properties. Automated search and decision procedures alter the cost of finding proofs and counterexamples. Their combination in a modern tool is often a documented technical hybrid, but a shared word such as “state,” “logic” or “verification” is not evidence of historical descent.

The typed genealogy therefore distinguishes documented influence, documented adaptation, a shared problem, parallel development, criticism and reaction, and analogy. For example, the inspected CESAR text provides a documentary basis for a CSP relationship. RustBelt's use of a particular concurrent separation-logic framework is an explicit technical dependence, and the relaxed-memory follow-up is a documented continuation with changed assumptions. By contrast, the temporal proximity of two model-checking papers does not establish that one derives from the other. The Turing archive gives an antecedent date, not a complete causal path. [N003](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S046](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [N011](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [N001](../SOURCE_MAP.md#s-ef8b5e90ae1cf427).

A useful genealogy also follows changes of problem. A frame rule addresses local reasoning about a part of a state while protecting facts about the rest; aliasing conditions make that promise nontrivial. Refinement typing connects predicates and type checking, but evaluation strategy can change the soundness argument. ## 3. Formal verification and the caricature of formality

A formal-looking document is not automatically a verification result. The relevant distinction is whether a well-defined claim has been connected to evidence by an applicable inference. A long specification can omit the behavior that matters. A short assertion can decisively expose it. A green proof script can establish an intentionally narrow lemma or the wrong application statement. A failed proof can reveal a real defect, an inadequate invariant, a false assumption, a modeling error or merely an automation limitation. Those outcomes require diagnosis rather than a binary judgment about “formality.” [C02](../SOURCE_MAP.md#s-0be00f7164600b45), [C03](../SOURCE_MAP.md#s-0be00f7164600b45), [C09](../SOURCE_MAP.md#s-0be00f7164600b45).

The corresponding anti-caricature is equally important. A model-only theorem does not need a deployed system to be true. A passive monitor need not control the system to be useful. A bounded search need not prove an unbounded theorem to find a decisive counterexample. A qualitative cost judgment need not invent monetary precision. A reusable component guarantee can survive when it does not settle the whole application. The native negative population rejects universal slogans, not these legitimate narrow results. [P036](../SOURCE_MAP.md#s-460b1f2b7104c948), [P043](../SOURCE_MAP.md#s-460b1f2b7104c948)–[P048](../SOURCE_MAP.md#s-460b1f2b7104c948); [C01](../SOURCE_MAP.md#s-0be00f7164600b45), [C10](../SOURCE_MAP.md#s-0be00f7164600b45), [C14](../SOURCE_MAP.md#s-0be00f7164600b45).

This makes proportionality a scientific constraint. Evidence should discriminate alternatives that could change the intended decision. If an exhaustive four-row truth table already establishes the exact Boolean function, adding a general theorem-prover workflow is not an automatic improvement. If a transition system permits unbounded executions, sampling a few traces is not an adequate substitute for the universal claim. The appropriate burden follows the proposition and consequence, not the prestige of a named tool. The lightweight tradition supports deliberate partiality, and the current cases preserve an adequate simple control. [S015](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); [C06](../SOURCE_MAP.md#s-0be00f7164600b45), [C14](../SOURCE_MAP.md#s-0be00f7164600b45).

Ceremony becomes a problem when an activity is used as a proxy for an unsupported conclusion: counting annotations as correctness, treating certification recognition as proof of a specific system, treating a benchmark headline as independent replication, or requiring a new control after the decision is already adequately resolved. Necessary records, explicit assumptions and reproducible artifacts are not thereby ceremonial. Their value is the uncertainty they remove. [S051](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S052](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S101](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); [P038](../SOURCE_MAP.md#s-460b1f2b7104c948), [P041](../SOURCE_MAP.md#s-460b1f2b7104c948), [P042](../SOURCE_MAP.md#s-460b1f2b7104c948).

## 5. Claim formation: precision, relevance and conditional validity

A formal claim has at least a statement, interpretation and domain. A result about integers may change when implemented with fixed-width arithmetic. A claim about one object may not survive aliasing. A temporal formula may rely on which actions count as observations. A requirement such as “the service always answers quickly” leaves both the admitted failures and the response bound unspecified. Formalization helps expose these choices; it cannot decide the stakeholder's intention merely by selecting notation. The assertional sources motivate precise logical relationships, while requirements-oriented sources in the native account preserve the distinction between machine descriptions and world phenomena. [S001](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S002](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S081](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S082](../SOURCE_MAP.md#s-ef8b5e90ae1cf427).

The useful structure is conditional: under assumptions A and semantics M, evidence E supports proposition P. An application adds another question: does M represent the relevant implementation, environment and intended requirement? These questions can have different answers. A proof of P can be valid while A is false in the application. A theorem under inconsistent assumptions is logically entailed but cannot support an application requiring a realizable A. A theorem about a deliberately restricted domain can be exactly the intended contribution. Precision, satisfiability, non-vacuity, relevance and correspondence must therefore be examined separately. [C01](../SOURCE_MAP.md#s-0be00f7164600b45), [C02](../SOURCE_MAP.md#s-0be00f7164600b45), [C09](../SOURCE_MAP.md#s-0be00f7164600b45).

The current six-family profiles preserve the native instantiation questions. Their FORMAL_STATEMENT fields generally ask a future consumer to specify a proposition; they are not propositions that this study has proved for an unspecified target. The added current profile records identify the logical class and the remaining instantiation duties, and link actual case objects where an explicit local model exists. That prevents two errors: treating an uninstantiated duty as executed proof, and treating a useful research-level criterion as worthless because no target repository was supplied. [AUDIT_PROFILES.json](../SOURCE_MAP.md#s-dc74e68b340330ad).

A strong specification review asks for discriminating examples. Which behavior must be allowed? Which must be excluded? Does a weakening make the check green while discarding the intended requirement? Could two translations agree because they share the same omission? What explicit, inexpensive oracle would expose that mistake? The AI round-trip construction demonstrates shared omission without making a claim about a particular deployed language model. A direct truth table is retained as an adequate positive control for a small complete domain. [C02](../SOURCE_MAP.md#s-0be00f7164600b45), [C13](../SOURCE_MAP.md#s-0be00f7164600b45), [C14](../SOURCE_MAP.md#s-0be00f7164600b45).

## 6. Invariants, safety, liveness, fairness and property classes

For a transition system with initial states Init and step relation T, an inductive invariant I satisfies initiation and consecution: every initial state satisfies I, and every T-successor of an I-state satisfies I. If I implies a desired state predicate P, reachability establishes P on every reachable state. This is a sufficient proof route. P itself can be true on every reachable state yet fail consecution at an unreachable state included in P. Strengthening the invariant, restricting the domain appropriately or proving reachability directly can resolve the distinction. The native P006 already recognizes it; the current case supplies an explicit witness and positive control. [S001](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S003](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); [C03](../SOURCE_MAP.md#s-0be00f7164600b45).

Safety rules out a bad behavior; liveness requires that a good event eventually occur. A system that remains forever in a safe waiting state may satisfy one while violating the other. Termination is a particular progress requirement and changes the burden of a program-logic judgment. Weak fairness and strong fairness constrain different forms of persistent or recurring enablement. Neither an eventuality nor fairness alone supplies a numerical service deadline. In the finite lasso construction, schedules separate the fairness conditions, and arbitrarily long finite delays remain compatible with the relevant eventuality. A deadline requires a bounded-response statement and timing model. [S006](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S086](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); [C04](../SOURCE_MAP.md#s-0be00f7164600b45).

Property class affects the method. A predicate about one state differs from a property of a trace. A noninterference condition can compare sets of traces or observations across secret inputs, so ordinary trace inclusion does not automatically preserve it. In the author's finite example, a nondeterministic system exposes the same output set for each secret, while a deterministic refinement selects an output equal to the secret. Allowed behaviors shrink, yet that relational security property is lost. Another refinement that always selects one fixed output preserves it. This is a precise warning about a particular hyperproperty and refinement relation, not a claim that refinement cannot preserve security. [S021](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); [C15](../SOURCE_MAP.md#s-0be00f7164600b45).

Probabilistic, quantitative, timed and hybrid claims require their own domains and proof rules. The native survey's awareness of those classes is preserved, but this revision has not rederived specialized probabilistic or hybrid-system theorems. A qualitative fairness example cannot discharge a probability bound, and a source-level timing abstraction cannot establish physical response times without its correspondence assumptions. This is an explicit boundary of current inquiry, not an implied rejection of those methods. [COVERAGE.md](../SOURCE_MAP.md#s-4524c8c6ff833389), module FM02.

## 7. Contracts, ownership and compositional proof

A contract can establish a useful local relationship without solving a whole system. To use a producer's guarantee to discharge a consumer's assumption, the relevant implication must hold under compatible semantics, state interpretation and environment conditions. A producer promising x ≥ 0 does not satisfy a consumer requiring x > 0. Strengthening the guarantee to x ≥ 1 repairs that particular interface. The local fact x ≥ 0 remains true; only the attempted composition fails. This distinction protects useful partial contributions from all-or-nothing judgments. [C07](../SOURCE_MAP.md#s-0be00f7164600b45).

Frames and ownership make compositional reasoning possible when operations affect only a portion of state. Aliasing can invalidate a naive assumption that an apparently separate cell is unchanged. The inspected separation-logic discussion motivates explicit control over such interference; it is not evidence that every implementation of every logic has been independently validated. The local author construction shows an alias changing the supposedly protected value, then a disjoint-state control in which the intended frame is justified. [S048](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S049](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); [C08](../SOURCE_MAP.md#s-0be00f7164600b45).

Circular assumptions require care rather than a blanket prohibition. Merely assuming A to prove B and B to prove A does not establish either: both can be false. Sound assume-guarantee rules can nevertheless use circular structure when their temporal, induction or closure conditions justify it. Abadi and Lamport's composition work is a relevant primary source for that stronger distinction; only the selected inspected portions are claimed here, and extraction losses in notation are recorded. The case compares an unsupported two-implication argument with simultaneous induction from an established base. [N004](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); [C07](../SOURCE_MAP.md#s-0be00f7164600b45).

Composition is therefore a relation with remaining premises. It can discharge an interface assumption, establish a frame or reduce a larger obligation without proving system progress, correct deployment or adequate requirements. The reverse direction must be examined independently: a system goal can suggest an interface contract, but it does not prove that a component meets it. The composition register makes the shared object, guard, partial contribution, reverse, counterexample, cheap alternative and authority boundary explicit. [COMPOSITION.md](S-c226a3bf7db4e6db-DRF-L3-COMPOSITION.md), R03.

## 8. Abstraction and refinement: inference direction matters

An abstraction is useful when it preserves the distinction needed for a claim at a manageable cost. A sound over-approximation can include every concrete behavior plus additional ones. If every abstract behavior satisfies a universal safety condition, the concrete behaviors do too. An abstract violation may instead be spurious. A sound under-approximation can provide a real witness to some behavior; the absence of a witness in that subset cannot establish universal safety. These are different inference directions, not competing labels of good and bad abstraction. The abstract-interpretation and counterexample-guided-refinement sources support their historical and methodological roles at the access scopes recorded here. [S005](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S061](../SOURCE_MAP.md#s-ef8b5e90ae1cf427).

The finite construction makes the directions inspectable. A concrete set contains 0 and 2. An over-approximation adds 1, which creates an abstract counterexample to a property true on the concrete set. An under-approximation containing only 0 is useful for an existential witness but misses the behavior at 2. Refining a spurious counterexample can improve the model, but the refinement operation itself needs to retain the intended relation. The case establishes these exact set relationships, not the soundness of a named industrial analyzer. [C05](../SOURCE_MAP.md#s-0be00f7164600b45).

Refinement must name the property it preserves. Simulation, trace inclusion, observational equivalence and information-flow relations answer different questions. A theorem can be correct under a relation that is too weak for the user's security or timing question. The hyperproperty case shows why a generic phrase such as “the refined system has fewer behaviors” is insufficient for all relational properties. A useful current claim therefore identifies both the relation and the preservation theorem or direct argument relevant to the chosen class. [S021](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); [C15](../SOURCE_MAP.md#s-0be00f7164600b45).

Cost and uncertainty remain. A more detailed model can remove spurious counterexamples while increasing state space and maintenance burden. An intentionally coarse model can settle an architectural question without representing implementation data structures. A model-only theorem remains legitimate if external correspondence is not its claim. The cheap path is the least expensive representation that resolves the material distinction, not an obligation to model every detail. [S015](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); [P013](../SOURCE_MAP.md#s-460b1f2b7104c948)–[P015](../SOURCE_MAP.md#s-460b1f2b7104c948).

## 9. Model checking, finite completeness and counterexamples

Model checking can decide a specified property for a specified finite model when the exploration and algorithm complete under their assumptions. That is a complete result at the model's domain, even when the domain is not a deployed implementation. A bounded exploration of a larger or unbounded system establishes a different claim: no counterexample within the completed bound. A timeout or resource exhaustion is different again. Calling all three “no bug found” discards the distinction that makes the evidence useful. [C01](../SOURCE_MAP.md#s-0be00f7164600b45), [C06](../SOURCE_MAP.md#s-0be00f7164600b45).

The author's graph examples separate a completed exploration at depth two, a counterexample first reachable at depth three, a search interrupted by its own budget and exhaustive exploration of a finite cyclic graph. A cycle does not necessarily prevent complete state exploration when previously visited states are handled correctly. Conversely, choosing a bound does not make the original system finite. The output records the explored domain, completion status and witness, rather than deriving a universal result from a green return code. [C06](../SOURCE_MAP.md#s-0be00f7164600b45).

The public description of Alloy required both an identity repair and a current-version qualification. The native public fact F07 linked the Alloy claim to CSP. The historical Alloy book remains the relevant native source identity, while current official Alloy 6 documentation describes temporal analysis, including bounded exploration and a complete mode over finite universes. “Alloy is only bounded” is therefore not a safe version-independent assertion. ## 10. Proof engineering, kernels and maintained artifacts

A proof artifact is evidence about a proposition under a logic and its assumptions. Interactive provers can separate complex proof search from a smaller checking core, but the actual trusted boundary depends on the system and the features used. Axioms, admitted statements, native evaluation, external oracles, parsers and translation paths can change that boundary. The inspected Lean documentation illustrates why the operative configuration matters; the failed version-specific route and the actual latest-documentation access are both recorded. This is not a blanket accusation against an assistant or a proof whose assumptions are explicit. [N006](../SOURCE_MAP.md#s-ef8b5e90ae1cf427).

Proof maintenance is an engineering burden distinct from theorem truth. A library API change can break a script for a theorem that remains true. A new tactic can re-establish the same statement without altering the claim. A weakened statement can make a script green while abandoning the earlier requirement. The Isabelle compatibility study reports a large population of compatibility issues across its examined versions and archive, not an equal number of logical soundness defects. Its discovery procedure, including skipped statements, is not evidence that skipped proofs were accepted as completed results. [S095](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); [C12](../SOURCE_MAP.md#s-0be00f7164600b45).

Human and organizational evidence helps explain maintenance costs but has a different ceiling. The examined Coq user survey is a self-selected community study; its 2022 respondents, later publication and summaries are one cohort. The Dafny interview study concerns 14 experienced developers recruited through referral and related routes, not a random sample of all programmers. Their reported difficulties and practices can inform hypotheses and design choices, but they do not establish a causal productivity effect for every adoption. [S076](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S100](../SOURCE_MAP.md#s-ef8b5e90ae1cf427).

The appropriate response is affected-scope reasoning: identify the statement, assumptions, dependencies and changed interfaces, then replay or inspect the part whose evidence could have changed. Retain historical evidence as history. A complete rebuild may be appropriate when dependency boundaries are unknown; a narrowly justified replay can be adequate when they are known. This is a conditional maintenance discipline, not a universal demand to erase old proofs or rerun every artifact after an unrelated edit. [P021](../SOURCE_MAP.md#s-460b1f2b7104c948)–[P023](../SOURCE_MAP.md#s-460b1f2b7104c948), [P048](../SOURCE_MAP.md#s-460b1f2b7104c948); [C12](../SOURCE_MAP.md#s-0be00f7164600b45).

## 11. SAT, SMT and symbolic execution: the answer belongs to the query

A satisfiability result concerns the encoded formula, theory and selected semantics. A satisfying assignment can be checked against that formula. An unsatisfiability certificate can support a separate checking path, but the certificate language, proof rules, checker and formula parser still matter. The author's small SAT and resolution examples include a valid witness, a checked contradiction, a tampered certificate rejected by the checker and an arithmetic encoding that changes its meaning under fixed-width interpretation. ## 12. Static analysis and types: name the guarantee and the escape

Static analysis can compute information about possible executions without running every execution. Its soundness claim is relative to an explicit language, environment and analysis semantics. A sound over-approximation may report false alarms; a deliberate unsound option may trade completeness of bug detection for speed or usability. A documented scope exclusion is not automatically an implementation defect. An implementation that violates its own promised analysis semantics is a different matter. The toy analyzer construction makes an explicit escape miss a bad state; it is not an allegation that a named tool contains that defect. [C05](../SOURCE_MAP.md#s-0be00f7164600b45), [C19](../SOURCE_MAP.md#s-0be00f7164600b45).

The inspected Astrée material is historical project documentation with explicit restrictions on the C subset and kinds of runtime errors addressed. It does not justify a claim about every current commercial version or all C programs. This distinction matters because a successful sound analysis under a restricted execution model can be a real achievement without being complete general software verification. When an application falls outside the model, the required response is to identify the gap, not to discard the theorem that was actually established. [S032](../SOURCE_MAP.md#s-ef8b5e90ae1cf427).

A type guarantee must likewise be named. A program can return an integer of the correct type while computing the wrong arithmetic function. Richer type systems may encode substantial functional specifications; it would be equally mistaken to say that types can never establish functional correctness. The current claim rejects both universal slogans. The case uses a deliberately weak type property and a stronger intended function to show their difference. [P027](../SOURCE_MAP.md#s-460b1f2b7104c948), [P046](../SOURCE_MAP.md#s-460b1f2b7104c948); [C08](../SOURCE_MAP.md#s-0be00f7164600b45).

Refinement types add predicates to the checking problem and often rely on solver reasoning. The inspected LiquidHaskell material highlights a semantic issue: a verification-condition treatment suitable for eager execution cannot simply be transferred to lazy evaluation. Termination and stratification contribute to the repair in that work. The current inquiry accessed the author's abstract and indexed primary material, not a complete reproduction of the benchmark or implementation. Its value here is the source-supported warning that the host language's evaluation semantics is a premise, not a formatting detail. [S047](../SOURCE_MAP.md#s-ef8b5e90ae1cf427).

The useful cheap path can therefore be an ordinary type, a refinement, a local assertion, an abstract domain or a test, depending on the failure distinction. Escalation is justified by the unproved property, not by the general claim that one tool family is always stronger. The full evidence partitions retain formal soundness, actual mechanical replay, implementation correspondence and industrial experience as separate dimensions. [PROPERTY_LEDGER.json](../SOURCE_MAP.md#s-abdf256ca3709fcb), P026–P028.

## 13. Concurrency, distributed systems and memory assumptions

Concurrent reasoning depends on what executions the model admits. Atomicity, interference, failure and communication assumptions affect both safety and progress. A sequentially consistent execution model is not interchangeable with a weak-memory architecture. A reliable-channel model is not a theorem about arbitrary message loss. A crash-fault model is not automatically Byzantine fault tolerance. These distinctions can be legitimate choices when the claim is stated at that scope. The failure is the unsupported transfer to a broader setting. The native records retain process algebras, temporal methods, parallel proof rules and distributed-system examples as separate contributions. [S017](../SOURCE_MAP.md#s-ef8b5e90ae1cf427)–[S020](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S030](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S031](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S087](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S088](../SOURCE_MAP.md#s-ef8b5e90ae1cf427).

Linearizability requires an appropriate sequential explanation of a concurrent history while respecting the relevant real-time order of nonoverlapping operations. It is distinct from simply finding a serial ordering that ignores that order, and it does not by itself establish eventual completion. The inspected original paper provides the formal context, while the author's finite complete-history checker explores a small set of permutations under explicitly stated conditions. A completed write of 1 followed by a read returning 0 is rejected in the constructed history; a serial order that reverses their real-time relationship is not an adequate substitute. Pending invocations need the fuller definition and are discussed analytically rather than claimed to be implemented by this bounded checker. [S090](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); [C16](../SOURCE_MAP.md#s-0be00f7164600b45).

The memory-model construction provides another discriminator. Under the chosen sequentially consistent model, two threads' stores and reads produce three result pairs. Under the deliberately specified FIFO store-buffer model, a fourth pair appears through buffered stores. This is a finite example of why a proof under one memory semantics cannot be transferred by name to another. It is not a complete x86, ARM, C or Rust memory model. The native weak-memory frontier source was inspected only at its actual metadata scope; the stronger fresh primary support comes from the RustBelt follow-up. [S106](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [N011](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); [C17](../SOURCE_MAP.md#s-0be00f7164600b45).

RustBelt's original account explicitly uses a restricted language model and a sequentially consistent setting. The inspected relaxed-memory follow-up changes that setting and reports changes to atomic access ordering in a reference-counted component, including a race exposed in the course of the work. That is evidence of a meaningful extension and repair under new semantics. It is not evidence that the earlier theorem was false under its original assumptions, nor that the new paper proves all of Rust or all unsafe libraries. The actual model, interfaces and proof obligations define the result. [S046](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [N011](../SOURCE_MAP.md#s-ef8b5e90ae1cf427).

Testing can probe gaps left by formal models. The inspected distributed-systems study reports bugs in three verified systems and the behavior of its testing approach, which was developed using known bugs. Its counts do not supply a fair universal comparison between verified and unverified software. The preservation of a useful protocol guarantee is compatible with defects elsewhere in an implementation or deployment boundary. This study keeps those positive results visible while examining the remaining gap. [S092](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); section [17](#s17).

## 14. Runtime verification: observation, verdict and intervention

A runtime monitor reasons about observations available during or after execution. A passive monitor can be valuable because it detects a violation, provides an audit trace or prompts a human response. It need not have the authority or mechanism to alter the system. Enforcement and recovery are additional capabilities with different obligations. Requiring every useful monitor to control the plant would reject legitimate evidence; treating every detected violation as prevented would overclaim. [S066](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S068](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S099](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); [C10](../SOURCE_MAP.md#s-0be00f7164600b45).

Observability and timeliness matter. If the dangerous event is never delivered to the monitor, a clean observed trace does not establish a clean underlying execution. If processing finishes after the relevant deadline, even a correct verdict can be too late for a particular intervention. The author construction separates complete observation, a missing event, a late response and an active control with specified authority. It also includes a positive finite observation that establishes a particular co-safety event, so the account does not reduce monitoring to violation detection alone. [C10](../SOURCE_MAP.md#s-0be00f7164600b45).

Monitorability is itself a formal property whose quantifiers matter. The inspected survey's continuation-based condition does not promise that every actual run eventually receives a decisive verdict. A prefix may have a possible decisive continuation while the actual system follows another path indefinitely. The distinction between finite evidence for a violation, finite evidence for satisfaction and an indefinitely inconclusive trace depends on the specification class. A meaningful monitoring claim states which verdicts are sound and which traces may remain unresolved. [S099](../SOURCE_MAP.md#s-ef8b5e90ae1cf427).

Runtime overhead changes the use decision. Instrumentation, event transport, storage and analysis can impose costs or perturb execution. The inspected overhead study evaluates a particular Java/API setting and optimization approach; a borrowed threshold is not a universal acceptable slowdown. Reusing instrumentation can be a cheaper adequate improvement than changing the property or adding an independent monitor. The native framework's cost and nontrigger fields preserve that possibility. [S104](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); [P031](../SOURCE_MAP.md#s-460b1f2b7104c948), [P032](../SOURCE_MAP.md#s-460b1f2b7104c948).

## 15. Verified toolchains, translation validation and certificates

A compiler theorem connects behaviors across specified source and target semantics. The inspected CompCert 3.18 manual identifies a translation boundary between internal source representation and assembly representation; parsing, assembly, linking, execution environment and other interfaces have their own status. Undefined source behavior, admitted nondeterminism and resource or timing behavior matter to what can be inferred. The theorem's value is substantial precisely because its relation is defined. It should neither be inflated into whole-machine correctness nor rejected because some surrounding stages are unproved. [S110](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), with native historical identities [S024](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S094](../SOURCE_MAP.md#s-ef8b5e90ae1cf427).

The finite compiler-style construction distinguishes allowed source behaviors {0,1} from a target choosing {1}, which respects the selected inclusion, and a target producing {2}, which does not. It then separates a matching artifact identity from a different built artifact. The mathematical relation survives at the matching boundary; a checksum alone does not prove the semantic relation, and a theorem about one build does not automatically identify another. Timing and hardware behavior remain outside this toy relation. [C11](../SOURCE_MAP.md#s-0be00f7164600b45).

Translation validation changes the burden by checking a particular translation result rather than proving the entire translator once. The inspected Viper validation paper supports a per-run implication for a described intermediate representation and supported subset. Proof-carrying evidence similarly separates production from checking. A certificate can reduce reliance on a complex producer, but the trusted checker, certificate rules, parser and intended formula still require a justified boundary. A small checker can be easier to inspect; smallness is not a theorem of correctness, and a larger justified checker is not invalid merely by size. It does not itself reproduce the older HACL* proof or establish a universal absence of physical side channels. An algorithmic, memory-safety or source-level constant-time theorem has its own value; the property must be followed through compilation and execution before claiming the corresponding physical observation. ## 16. Vacuity, weak specifications and specification gaming

A formula can be true for an unhelpful reason. An implication with an impossible antecedent may hold while saying nothing about the intended operating condition. A temporal requirement may be satisfied because its trigger never occurs. A program can satisfy a postcondition that is too weak to distinguish the desired function. These are different mechanisms. Vacuity analysis, satisfiability checks and positive/negative examples help diagnose them, but no single syntactic check decides whether a specification captures a human purpose. The early vacuity source identity was corrected from the wrong chapter locator; the later native reference remains at its disclosed access scope. [S059](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S060](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); [C02](../SOURCE_MAP.md#s-0be00f7164600b45).

A logically valid theorem does not become invalid merely because it is weak. An intentionally narrow lemma can be necessary in a larger proof or useful for a different consumer. The error arises when that lemma is offered as evidence for a stronger proposition without a valid implication. Likewise, inconsistency is not inferred merely because an assumption is restrictive. The claim must identify which assumptions are jointly realizable in the intended domain and which consequences follow under them. [P002](../SOURCE_MAP.md#s-460b1f2b7104c948), [P020](../SOURCE_MAP.md#s-460b1f2b7104c948), [P039](../SOURCE_MAP.md#s-460b1f2b7104c948); [C02](../SOURCE_MAP.md#s-0be00f7164600b45).

“Specification gaming” can describe an observable optimization against an inadequate criterion, but intent must not be invented. An accidental omission, a deliberate simplification for a local lemma and a deceptive substitution can produce superficially similar proofs. This study diagnoses the statement and evidence relationship. It does not attribute motive to authors, tool builders or systems from a mismatch alone. The current profiles therefore ask what decision consumes the result, what behavior distinguishes success and whether the changed statement preserves that meaning.

The round-trip case extends the issue to generated formalizations. A forward translation and a backward explanation can share an omission, so their agreement is not independent evidence of complete intent preservation. A fixed intended statement and explicit discriminating examples provide a different check. The same risk applies to human pipelines and shared encodings; AI origin is not the defining logical fact. [S102](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); [C13](../SOURCE_MAP.md#s-0be00f7164600b45).

## 17. Proof, tests, fuzzing and empirical assurance

Proof and testing answer different questions when their objects or quantifiers differ. A proof can cover every execution admitted by a semantics; a test can expose that an actual interface, configuration or environment does not match the semantics. Fuzzing can find a counterexample in a tool used to generate evidence. Testing can also help develop an invariant or specification before a proof exists. None of these uses requires the slogan that every theorem must always be accompanied by a separate test campaign. Native P036 already preserves pure mathematical work and allows redundant tests to be reconsidered. [P036](../SOURCE_MAP.md#s-460b1f2b7104c948), [P044](../SOURCE_MAP.md#s-460b1f2b7104c948).

The inspected solver-fuzzing report distinguishes submitted bug reports, unique bugs, fixed bugs and soundness bugs. Those nested counts are not a probability that a random solver query is wrong, and multiple reports do not necessarily represent independent defects. Their scientific force is that tool implementation failures are real and discoverable in the studied setting. The relevant response can be a tool repair, a certificate check, a version restriction or an additional discriminator, depending on the actual claim. [S097](../SOURCE_MAP.md#s-ef8b5e90ae1cf427).

The distributed-systems testing study likewise separates formal protocol properties from implementation and environmental defects. Its three systems and bug set are a small selected population; development using known bugs limits a held-out effectiveness interpretation. The study nevertheless provides a concrete reason to examine boundaries that the formal result did not cover. The correct inference is neither “verification failed completely” nor “the proof makes those bugs irrelevant.” [S092](../SOURCE_MAP.md#s-ef8b5e90ae1cf427).

Recent unit-proof work reports another useful but bounded practice. In the inspected v1, 73 proofs across four operating systems were evaluated against 89 reintroduced defects, with initial detections, later interventions and remaining misses distinguished. The reported execution mean is 61 seconds for all 73 proofs, excluding compilation. Development effort has a within-source disagreement: the abstract and introduction report a mean of 87 minutes, while the RQ3 finding reports 82 minutes. The actual development mean remains unresolved without artifact analysis or an authenticated correction; neither figure is selected here as correct. Development timing covers the last 21 proof tasks after 52 earlier tasks used to gain experience. These populations and measurements are not interchangeable, and the source's selected defects do not establish a universal defect-detection rate. The author's earlier interim transcription of seconds as minutes remains explicitly corrected in the inquiry record; the newly disclosed 87/82 disagreement is a separate observation. [S107](../SOURCE_MAP.md#s-ef8b5e90ae1cf427).

A hybrid evidence package should therefore name its complementary contribution. A monitor might challenge an environmental premise; a test might validate an interface convention; a proof might cover combinations too numerous to test. If all components share the same wrong encoding, extra activity need not add semantic independence. The composition register records a useful partial proof/observation relation and rejects a fabricated universal novelty claim. [COMPOSITION.md](S-c226a3bf7db4e6db-DRF-L3-COMPOSITION.md), R06 and V01; [C01](../SOURCE_MAP.md#s-0be00f7164600b45), [C09](../SOURCE_MAP.md#s-0be00f7164600b45), [C10](../SOURCE_MAP.md#s-0be00f7164600b45).

## 18. Currentness, replay and semantic change

Currentness concerns whether evidence still supports its present use. An unchanged theorem remains true under the same interpretation even if a tactic or library interface changes. A new deployment environment may invalidate a correspondence premise without changing the theorem. A changed specification may strengthen, weaken or redirect the obligation. A green proof after such a change must be compared at the statement level, not only the tool-result level. The currentness construction separates all three situations. [C12](../SOURCE_MAP.md#s-0be00f7164600b45).

The affected scope depends on the change. Renaming a proof helper can demand mechanical repair without semantic requalification. Changing an integer model to bounded arithmetic can alter the theorem. Changing a build, parser or compiler can alter which artifact a result concerns. Changing a consumer can make a previously sufficient narrow property insufficient for the new decision. The appropriate identity record includes the proposition, semantics, assumptions, tool configuration and correspondence boundary relevant to that use. It need not bind irrelevant details simply to maximize record volume. [P023](../SOURCE_MAP.md#s-460b1f2b7104c948), [P048](../SOURCE_MAP.md#s-460b1f2b7104c948), [P050](../SOURCE_MAP.md#s-460b1f2b7104c948).

The proof-maintenance sources illustrate costs and failure modes, not a universal demand for maximal replay. The Isabelle compatibility study counts compatibility issues under its own discovery procedure; a broken script is not necessarily a false theorem. Proof-repair benchmarks and community surveys describe further mechanisms and experience at different scopes. Where the native source was not freshly inspected, the current carrier retains it as a lead rather than presenting its details as newly confirmed. [S074](../SOURCE_MAP.md#s-ef8b5e90ae1cf427)–[S076](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S095](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S096](../SOURCE_MAP.md#s-ef8b5e90ae1cf427).

Reuse can be justified when the relevant boundary remains within established limits. The inspected FAA reusable-software guidance explicitly addresses such bounded reuse and affected changes; it does not imply that every reuse requires an identical new approval process or that no further assessment can ever be needed. Normative acceptance conditions are kept separate from mathematical truth and empirical reliability. [S113](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); [C18](../SOURCE_MAP.md#s-0be00f7164600b45).

## 19. Lightweight and cost-effective use

Lightweight formal methods are not merely incomplete attempts at a maximal proof campaign. Partiality can be deliberate in the language, model, analysis or composition. A small model can expose an architectural inconsistency before implementation. A contract can clarify one hazardous interface. A bounded check can find a concrete failure. A type can rule out a class of mistakes at low recurring cost. The 1996 source makes selectivity central; the current claim retains it as a legitimate contribution rather than a concession that needs an apology. [S015](../SOURCE_MAP.md#s-ef8b5e90ae1cf427).

The cost question is comparative and local. What uncertainty affects this decision? What loss follows if the unsupported inference is wrong? Which cheaper method would discriminate the same alternatives? What expertise, annotations, compute, integration and maintenance does the proposed method require? These questions can often be answered qualitatively. The study does not fabricate return-on-investment percentages where the sources provide interviews, selected cases or perceptions. A justified decision to continue with an adequate existing control is an admissible outcome. [P037](../SOURCE_MAP.md#s-460b1f2b7104c948), [P042](../SOURCE_MAP.md#s-460b1f2b7104c948); [C14](../SOURCE_MAP.md#s-0be00f7164600b45).

The industrial evidence supports practical possibilities more strongly than universal cost superiority. The 2009 survey assembled 62 projects through stated collection routes, including direct contributions and literature cases. The 2020 study reports perceptions from a nonrandom population. The recent industry review selects successful experience rather than drawing a random comparison sample. The examined Dafny and Dezyne interview studies provide detailed accounts from experienced or vendor-referred users with their own selection limits. Such evidence can reveal mechanisms, barriers and contexts; it cannot alone estimate the average causal effect of adoption across all software work. [S062](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S064](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S065](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S100](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S112](../SOURCE_MAP.md#s-ef8b5e90ae1cf427).

The author's complete four-input truth table supplies a small positive control: the exact function is established at that finite domain without an added workflow. It does not prove that truth tables scale to large state spaces. A different consequence, larger domain or changing semantics can legitimately trigger stronger evidence. Proportionality is therefore neither an automatic preference for the cheapest activity nor an excuse to leave a consequential quantifier unsupported. ## 22. Criticism: what each challenge does and does not establish

The first criticism concerns the specification and world boundary. De Millo, Lipton and Perlis challenge accounts of program verification that disregard social and practical validation; the native Fetzer record raises a related program/execution distinction, but current access to the full argument remains limited. Requirements-oriented work gives another path into the machine/world problem. The surviving response is to distinguish theorem validity, statement relevance and external correspondence. That response does not refute every philosophical objection, and it does not require a mathematical lemma to solve an entire social problem. [S055](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S056](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S081](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S082](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); [CRITICISM.md](../SOURCE_MAP.md#s-19a88c6e4bcd8543), K01.

The second criticism concerns tractability and cost. Expressive logics can be difficult or undecidable to automate; finite models can still be too large; proofs and specifications require expertise and maintenance. Lightweight modeling, abstraction, bounded analysis, incremental checking and selective proof are responses to those burdens. They are not guarantees that every effort pays for itself. The empirical studies support contextual experience and reported barriers, while their sampling prevents universal causal claims. Hall's rejection of sweeping myths helps resist both exaggerated promises and blanket dismissal. [S015](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S057](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S062](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S064](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S100](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S112](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); K02–K03.

The third criticism concerns inference across boundaries. An abstraction can admit spurious traces; a refinement can fail to preserve a relational property; contracts can have incompatible or circular assumptions; aliasing can invalidate a frame; a memory model can omit an execution; a compiler theorem can leave an unproved interface. These are reasons to state and check the relevant relation. They do not establish that abstraction, modularity or compilation proofs are intrinsically futile. The current cases provide both failure witnesses and positive controls, and the primary sources supply the historical mechanisms at their recorded scopes. [S021](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S048](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [N004](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [N011](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S110](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); K04–K05 and K13.

The fourth criticism concerns evidence production. Solvers and translators can contain defects; proof scripts can drift; benchmark descriptions can conceal dependence or unequal comparisons; monitoring can miss events; generated formalizations can preserve a shared omission. Checking certificates, reconstructing proofs, retaining exact statements, measuring observation gaps and comparing adequate baselines are useful responses. They leave residual trust and semantic duties, and their overhead can itself affect a use decision. Tool agreement is not independent corroboration when the tools share the same erroneous input translation. [S097](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S095](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S099](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S102](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S108](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); K06–K09 and K12.

The fifth criticism concerns claims made from industry and standards. A selected deployed system demonstrates possibility and may reveal a useful mechanism. It does not by itself estimate comparative defect reduction or cost. A survey respondent's intended use is not realized effectiveness. A document's normative recognition is not an independent empirical study. The dependence register groups repeated cohorts, versions and projects so that a bibliography cannot masquerade as replication. [S062](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S064](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S065](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [N009](../SOURCE_MAP.md#s-ef8b5e90ae1cf427), [S051](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); K10–K11.

The criticism ledger preserves the strongest conditional alternative to each response. For example, a sound circular proof rule is possible; a valid pure theorem can need no empirical check; richer types can establish functional properties; a finite exhaustive result can be complete; and an unchanged accepted component may be reusable without indiscriminate requalification. A criticism that disappears when confronted with these alternatives is too broad to retain as a universal property.

## 24. Internal tensions and decision criteria

Formal-methods practice contains tradeoffs that cannot be resolved by choosing the strongest-sounding method. More expressive statements can demand more difficult proofs. A coarser abstraction can complete quickly but generate spurious counterexamples. A smaller trusted core can require more elaborate proof reconstruction. More runtime observation can increase overhead and affect the execution being observed. More complete formalization can improve coverage while consuming resources needed for implementation, testing or maintenance. These are conditional engineering tensions, not contradictions in the idea of formal reasoning.

| Tension | Useful discriminator | Admissible restrained outcome |
|---|---|---|
| Expressiveness and automation | Does the extra expressiveness distinguish a consequential behavior? | Keep a tractable fragment when it answers the question. |
| Abstraction precision and scale | Is a counterexample real, spurious or outside the intended domain? | Refine only the detail needed for the selected property. |
| Local modularity and interference | Are assumptions compatible and frames protected? | Retain a useful local theorem while reopening composition. |
| Checking trust and reconstruction cost | Which producer, parser, rule or kernel is trusted? | Use an explicit justified boundary without requiring a universally minimal checker. |
| Monitoring coverage and overhead | Can missing or late events change the required verdict or response? | Keep passive detection where intervention is not the claim. |
| Reuse and currentness | Which changed dependency can affect this proposition or use? | Replay the affected scope and preserve old evidence as history. |
| Strong proof and cheap adequate evidence | Does a simpler method discriminate the same complete domain? | Use the truth table, assertion, direct proof or existing control. |
| Automation and intent | Is the checked statement independently connected to the intended requirement? | Keep a checked narrow result without upgrading semantic relevance. |

The table is supported by the specific counterexamples, positive controls and source-scoped arguments developed in sections 5–20; it is not a quantitative optimization model. The full tension records retain the linked native properties. Empirical superiority would require a stated population and comparison design not supplied by these author constructions. ## 25. Hybridization and guarded composition within this lineage

The current analysis asks whether one retained property materially contributes to another under a shared object and guard. Co-occurrence in a project is not enough. Each relation names what it discharges, what remains open, an independently examined reverse direction and a cheap alternative. ## 28. Rejected, superseded and assumption-sensitive forms

The native rejected population contains useful boundary claims. “Prove everything” is not a general engineering rule: a complete proof can be appropriate for a selected object, but proof effort must still serve a consequence-sensitive question. “Proof eliminates testing” is likewise too broad, while a particular redundant test may reasonably be retired when its evidential role is already discharged. “The model is the real system” omits correspondence, while an exact finite model can still be the entire object of a legitimate theorem. “Type safety is functional correctness” confuses guarantees, while richer types can express and establish functional properties. [P043](../SOURCE_MAP.md#s-460b1f2b7104c948)–[P046](../SOURCE_MAP.md#s-460b1f2b7104c948).

P047 remains assumption sensitive rather than being converted into a rejection of proof assistants or generated proofs. A checked proof can be sound under explicit axioms and a trusted boundary; an unexamined statement, axiom or translation can defeat a broader assurance claim. The current qualification protects both the checked result and the unresolved semantic burden. The source access and case distinctions prevent a tool brand or an AI origin from deciding the result by itself. [P047](../SOURCE_MAP.md#s-460b1f2b7104c948), [N006](../SOURCE_MAP.md#s-ef8b5e90ae1cf427); [C13](../SOURCE_MAP.md#s-0be00f7164600b45).

A documentary mechanism that identifies the claim and supports a real review has a different role from a count of forms used as a surrogate for correctness. Removing unnecessary activity is justified by maintaining adequate discrimination, not by declaring every control suspect. Supersession also needs an exact object. A source locator can be retired from current support because it points to a different work while the source identity remains preserved historically. A new tool version can supersede an old feature description without proving the old theorem false. A narrower current claim can replace an overbroad application assertion while retaining its valid core. ## 29. Current state and research frontier

At the current cutoff, the examined frontier includes proof-producing solver infrastructure, proof-assistant integration, maintained proof ecosystems, formalization and proof benchmarks, practical unit-level proofs, weak-memory extensions and runtime-monitoring theory. These are active developments with different evidence types. Some records are full selected primary passages, some are abstracts, some are official documentation and some are metadata-only leads. Several questions remain scientifically live after the present inquiry. How can semantic translation be challenged without reproducing the same omission in a second representation? Which proof-maintenance boundaries make affected-scope replay reliable at reasonable cost? How should monitorability, overhead and intervention delay be evaluated together for a particular use? Which properties survive a specified refinement when they compare multiple traces?
