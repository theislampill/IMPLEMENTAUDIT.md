The lineage’s starting distinction is among **definition, running instance, work item and external object**. A model is a description of possible behaviour, while a particular run has actual state and obligations. A work item may be enabled but lack an authorised, capable or available actor. A message may be sent without being received, and an engine can finish while its recipient still lacks the intended result. A usable composition therefore joins control, data, resources, interactions and observations under the conditions that actually apply. It does not treat a diagram or completion label as the whole operating world. [Ledger EWM-001 and current public-documentation intake.]

## Predicates that must remain distinct

**Semantics and implementation correspondence.** Specified behaviour and observed implementation behaviour require a connection at the relevant engine/version/configuration. Pattern coverage or a standards badge is not sufficient. A formal model can provide a useful oracle or constraint even before an engine claim is established; the model’s inability to prove the entire receiver does not make that partial input immaterial. [Native relation R011; formal evidence cards; current report.]

**Progress and acceptance.** Possible completion, proper completion, deadlock freedom and inevitable termination are different claims. Real capacity, fairness or scheduling assumptions and the actual environment may matter. A successful test command can establish that a workflow ran without establishing that its scientific or business output is correct. The output oracle and receiving predicate must match the actual consumer. Loops, concurrency, streaming and interruptions remain legitimate structures; the field is not universally a DAG or serial pipeline. [Ledger EWM-011; sources on workflow soundness, Taverna and result validation.]

**Authority and external effects.** Enabling, permission, capability, availability and achieved effect are separate. A timeout can leave an external outcome unknown. Cancellation has a scope; it need not undo an already completed outside action. Compensation is an additional fallible action rather than a guarantee of reconstructing the old world. Duplicate-effect control and exactly-once claims depend on the actual key, transaction, persistence, cooperation and effect boundaries. They cannot be imported from a narrower system into arbitrary external services. [Ledger EWM-018, 022, 036, 037, 044 and associated source records.]

**Version and instance meaning.** A valid new definition does not establish a valid move of a running case. Such a move can need current marking, data, completed work, pending callbacks, semantic compatibility and authority for changed obligations. Keeping supported old-version cases is a legitimate alternative when they remain acceptable. Old history is preserved rather than rewritten to make a new definition seem continuously applicable. [Ledger EWM-048, 073, 076; native revision boundaries.]

## The accepted repair: distinct triggers, not a compulsory migration route

The substantive r2 repair responds to the adverse fidelity findings without rewriting the entire scientific programme. It retains all 77 identities and dispositions, the exact prior subject and adverse history. R021 previously made unanticipated repair an exhaustive choice between migration and external reconciliation. The corrected relation activates migration only when an existing case actually changes process semantics, and reconciliation only when an uncertain external action outcome requires it. Either, both or neither can apply. An authorised local reassignment or data correction under the same definition and without an outside effect can be a valid repair in its own right. Its permissions and consequences still matter. [Repair account, F01; model `r2_scientific_repair`.]

R036 now describes a compatible worklet as a conditional refinement of bounded exception repair, targeting EWM-033. A separately launched child case with compatible inputs and returned outputs need not migrate its parent. Routine late binding without an exception need not trigger that repair relation. A worklet can nevertheless fail through incompatible output, obsolete selection rules or lack of authority. The correction removes an unsupported universal endpoint; it does not prohibit a particular system from combining a worklet and a genuine migration when both actually occur. [Repair account; EWM-S036 and EWM-S037 selected passages attributed there.]
