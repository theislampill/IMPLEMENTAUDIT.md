`EVOLVED_RELIABILITY_AND_MAINTAINABILITY_ENGINEERING`.

It should **not** mean:

> “maximize MTBF and add redundancy.”

Test whether the evidence instead supports something closer to:

> an engineering discipline that defines the required function and operational
> profile before measuring failure; identifies propagation and common-cause
> mechanisms; designs fault detection, containment, degradation, repair and
> recovery as deliberately as nominal function; treats redundancy as useful
> only when its independence and switchover assumptions hold; binds reliability
> evidence to current configuration and representative exposure; and accepts
> recovery only when required function is re-established and observed.

Treat that sentence only as a hypothesis to test.

# Source standard

Prefer, according to claim:

1. original historical/primary sources;
2. foundational mathematical/engineering papers and monographs;
3. current authoritative standards/guidance where they directly establish
   engineering practice;
4. peer-reviewed empirical/field research;
5. systematic reviews/meta-analyses;
6. serious industrial/programme case studies with enough detail to establish
   engineering mechanisms;
7. strong criticism, replication and negative evidence;

# Adversarial duties

For every important property ask:

- What required function/failure definition does it protect?
- Is the operational profile representative?
- What independence/common-cause assumptions does the model rely on?
- Is a metric standing in for real mission/user consequence?
- Does redundancy really fail independently?
- Can standby/failover itself be latent-bad?
- Does detection coverage include the failure under discussion?
- Is repairability proved under actual support conditions?
- Does recovery re-establish required function or merely restart a component?
- Is a backup/restore path actually exercised?
- Is reliability evidence current after configuration change?
- Can a cheaper deterministic functional check establish the state?
- Does another chaos/fault-injection/reliability test change the decision enough
  to justify its cost?
- Did later practice retain, narrow, hybridise or reject the property?

`NO_GENERAL_PROPERTY` is a valid result.
