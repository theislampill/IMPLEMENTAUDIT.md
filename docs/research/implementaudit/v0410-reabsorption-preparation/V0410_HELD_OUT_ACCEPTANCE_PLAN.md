# V0.4.1 Reabsorption Held-Out Acceptance Plan

STATUS=`PREPARATION_ONLY`

BASELINE_RELEASE=`DEFER_TO_V0410_BASELINE`

The purpose of held-out evidence is to detect false completeness, copied
historical status, duplicate ownership and unjustified runtime transfer. It is
not a 658-case model benchmark and does not predetermine a source or RXX delta.

## Evidence partitions

| Partition | Claim it can support | Claim it cannot support |
|---|---|---|
| Packet/index identity | complete frozen denominator and exact locators | runtime transferability |
| Historical baseline | what earlier evidence recorded | current released-v0.4 disposition |
| Source inspection | implementation presence and owner paths | package/install/reachability |
| Package inspection | exact members and projection | host discovery or activation |
| Isolated install | installed contents and path resolution | correct model routing |
| Deterministic checker | discriminated mechanical predicate | irreducible cognitive judgement |
| Behavioural fixture | bounded activation/judgement under fixture conditions | universal effectiveness |
| Independent review | semantic challenge and omission detection | mechanical identity by assertion |
| Public readback | exact published object/asset availability | source semantics not inspected |

## Deterministic mutations

The campaign checker must reject each mutation against the actual canonical
ledger/checker path.

### H01 — Missing property

- Mutation: remove one row from the 658-row current disposition ledger.
- Expected: denominator failure; no completion claim.
- Detects: silent denominator shrinkage.

### H02 — Duplicate global key

- Mutation: duplicate one row under the same global property key.
- Expected: uniqueness failure even if row count remains 658.
- Detects: count-only gaming.

### H03 — Historical basis erased

- Mutation: clear `HISTORICAL_NONADOPTION_OR_PARTIAL_BASIS` on a historically
  partial, rejected, residual or unresolved row.
- Expected: fail before current reconsideration.
- Detects: rewriting history to make transfer look newly justified.

### H04 — Copied current disposition

- Mutation: copy historical disposition into current destination without a
  released baseline identity/currentness check.
- Expected: fail because required current evidence fields remain deferred or
  lack evidence identities.
- Detects: stale-plan bias.

### H05 — Source-presence overclaim

- Mutation: mark progressive disclosure complete from an existing reference
  path while the governor route cannot reach it.
- Expected: focused routing negative fails.
- Detects: source existence presented as activation.

### H06 — Package-presence overclaim

- Mutation: mark host reachability complete from package membership alone.
- Expected: isolated host/discovery evidence requirement fails.
- Detects: package/install/host conflation.

### H07 — Behavioural activation overclaim

- Mutation: mark behavioural activation complete from static source or checker
  evidence only.
- Expected: proof-level mismatch.
- Detects: mechanism presence presented as model behaviour.

### H08 — Deterministic discriminator fiction

- Mutation: cite checker source text without running a positive and a mutated
  negative through the checker.
- Expected: discriminator status remains insufficient.
- Detects: checker-name or grep-only proof.

### H09 — New RXX without genealogy

- Mutation: candidate record omits one of predecessor, overlap, dependency,
  authority-neighbour or duplicate-owner explanations.
- Expected: RXX admission schema/review failure.
- Detects: issue-number-first reasoning.

### H10 — New RXX quota

- Mutation: admission logic requires at least one new RXX or a target count.
- Expected: anti-gaming check fails.
- Detects: productivity theatre.

### H11 — Taxonomy-derived child

- Detects: one-skill-per-discipline proliferation.

### H12 — Existing-child collision

  `audit-implement` or `audit-andon` procedure/consumer/output without an

### H13 — Deterministic authority moved into cognition

### H14 — DAG title match

### H15 — Existing-owner amendment stretched

## Semantic held-outs

Select the held-out rows only after family partitioning, using a deterministic
seed derived from the exact released baseline identity. The reviewer that
adjudicates ordinary rows must not know which rows are held out.

Minimum strata:

1. one historically complete property per lineage;
2. one historically partial/amendment/residual property per lineage where the
   stratum exists;
3. every historical implementation/reachability gap;
4. every historical behavioural-proof gap;
5. at least one assumption-bound and one domain-bound row per trifecta;
6. at least one rejected/superseded row per lineage;
7. all rows tagged with an explicit absent deterministic discriminator;
8. a sample of explicit ceremony/cost rows from every represented lineage;
9. rows that touch multiple candidate RXX owners;
10. rows whose likely owner differs between deterministic substrate and model
    cognition.

Held-out reviewer questions:

```text
Can the current result be reconstructed from exact evidence without seeing the
ordinary lane's final label?

Does the cited owner establish the complete mechanism, or only share terms?

Would removing the cited path/check/route change the claimed behaviour?

Is a present reference actually reachable when warranted?

Does current v0.4 change feasibility, evidence, both or neither?

Has an assumption/domain boundary been silently erased?

Is the smallest truthful destination lower than the proposed one?
```

## State-derived terminal-orchestration discriminator

The hypothesis receives eight separately scorable cells:

| Cell | Positive evidence | Required negative |
|---|---|---|
| Automatic DAG derivation/recomputation | state change produces dependency-correct graph/frontier update | stale static plan is rejected |
| State-plan divergence | current state contradicts plan and forces explicit reconciliation | plan text cannot override current evidence |
| Unresolved-obligation derivation | obligations are mechanically reconstructible from evidence/state | omitted obligation blocks false closure |
| DONE/ACTIVE/READY/BLOCKED | complete, mutually coherent population | closed READY frontier catches missed work |
| JOIN/writer/authority/resource edges | disjoint lanes parallelise; shared writers serialize; JOIN required | duplicate writer and premature global conclusion fail |
| Progressive child routing | zero-or-one warranted child per derivation with governor return | hidden child chain and universal load fail |
| Currentness invalidation | changed identity invalidates only affected evidence | stale result cannot qualify new candidate |
| Recovery/re-entry | compact/current projection plus selective evidence reconstructs actionable state | stale checkpoint or hidden obligation fails closed |

Possible set results are `EXACT_EXISTING_OWNER`, `COMPOSED_EXISTING_OWNERS`,
`EXISTING_RXX_AMENDMENT`, `GENUINE_UNOWNED_RESIDUAL` or `UNRESOLVED`. No result
is preferred by the plan.

## Behavioural cells

Use model-in-the-loop evidence only for irreducible routing or judgement:

- route/no-route precision for a newly admitted reference or child;
- sibling-boundary discrimination among existing children and a candidate;
- non-trigger cheap path;
- direct-entry and governor-routed authority fences where applicable;
- evidence synthesis that cannot be reduced to deterministic checks;
- repeated value on ecologically distinct incidents.

Preserve one attempt per frozen fixture/model/configuration unless a transport
failure is mechanically established. Do not retry until green.
